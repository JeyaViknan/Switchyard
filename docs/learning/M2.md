# M2 — Console backend

## What was built
`src/switchyard/console/`: settings, a 1s collector building a snapshot from
four sources, Prometheus-text parsing with reset-safe rates and windowed p95,
a capped open-loop traffic generator, guided scenarios that score themselves
live, HMAC session auth, and an SSE API. 93 new tests, one end-to-end.

## Why
The gateway exposes monotonic counters; a live view needs rates, which means
differencing scrapes — and handling the two cases that breaks on: counters
reset to zero when the process restarts, and percentiles cannot be averaged,
so p95 is recomputed from histogram bucket deltas over the window.

Read-only endpoints are public so an interviewer can open the map on their own
phone; anything that generates load or injects faults needs a session. The
admin key stays in the console process and never reaches the browser.

## Interview questions

**How do you turn counters into a live view?** Keep the previous scrape,
divide the difference by elapsed time. A value lower than the one before means
the process restarted, so the delta is the new value — otherwise you render a
large negative spike. Percentiles come from differencing cumulative histogram
buckets, never from averaging per-scrape percentiles.

**Why is the load generator open-loop?** Closed-loop (fire, wait, fire again)
cannot offer more load than the system absorbs, so it can never show a tenant
being turned away — which is the whole noisy-neighbour story. Over the stream
cap it drops and counts rather than queueing, because queueing would quietly
make it closed-loop again.

**Your demo failed. What did you find?** Four real bugs. The biggest: clearing
a fault sent an empty patch, which the fleet correctly treats as "change
nothing", so the provider never recovered and the breaker's cooldown doubled
to 34 seconds. It presented as a flaky test.

**Why can the scenario checks fail?** Because they read the same measurements
the map draws. Checks start pending, not passing. A demo that cannot fail is
an animation, and an audience learns to ignore green that was never at risk.

**What's weak about the console's auth?** The cookie cannot be `Secure` — the
free-tier deployment is plain HTTP, so it would never be sent. Anyone on the
path can read it and press the demo buttons. It guards synthetic load against
a synthetic fleet, which is why that is tolerable; HTTPS is the first upgrade.
