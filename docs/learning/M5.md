# M5 — Build, scan, smoke, publish

## What was built
Four CI jobs: `check` (tests + both configs), `image` (buildx + GHA cache +
Trivy), `smoke` (production compose stack, real completion, sha match,
`switchyard verify`), `publish` (GHCR by commit sha, main only). Plus a
`terraform` job that stays inert until `infra/` exists, and `release.yml`
fixed so an unconfigured PyPI cannot suppress the image and release notes.

## Why
An image becomes pullable only after something has served a request with it.
Publishing on a green unit-test run asserts that the tests cover packaging,
networking and startup — they don't. The sha check closes the loop: `/readyz`
reports the sha baked in at build time, and the smoke test compares it to the
sha it shipped.

## Interview questions

**What does your pipeline actually gate on?** Lint, types, 467 tests, both
configurations, a Trivy scan, and a real streaming completion through a
five-container stack where the responding sha must equal the built sha. Only
then does anything reach a registry.

**Why ignore unfixed CVEs?** A finding with no patch available is information,
not something a merge can act on. A gate that cannot be satisfied gets
bypassed, and then it protects nothing. Failing only on fixable HIGH and
CRITICAL keeps it credible.

**The scan failed — what did you do?** Four HIGH advisories, all in tooling:
setuptools, and urllib3 and msgpack vendored inside pip. A service that runs
uvicorn never installs anything, so I removed pip, setuptools and wheel from
the runtime image. That deletes the vulnerable code rather than upgrading it,
and the image has one less executable thing in it.

**Why rebuild the image in the smoke job instead of passing it along?** With
the GHA cache the rebuild is seconds; moving a 200 MB tarball through the
artifact store and back is minutes. Separate jobs still tell me which stage
failed, without paying for the separation.

**Your release once published nothing. Why?** The GitHub release job depended
on the PyPI job, PyPI trusted publishing was not configured, so one optional
registry suppressed the container image and the notes as well. Optional steps
have to be optional in the dependency graph, not just in intent.
